How Identra SSO works

Three steps from login page to authenticated session.

1

Your app embeds the Identra login screen

Your existing login page posts the submitted username and password to Identra's auth endpoint instead of handling credentials itself.

2

Identra checks the submitted credentials

Identra binds to your directory using a dedicated service account, then runs a lookup built from the submitted credentials to locate a matching entry — under the hood this is typically done using LDAP for Active Directory to fetch the matching record.

3

Session established

On a match, Identra hands your app a session and redirects the user to the authenticated area of your site.

Full configuration keys and supported directory versions are in the docs.

What Identra runs on

Identra's auth service is a small Go binary, deployed as a container behind a managed load balancer. We run it across two regions so a single zone outage never takes internal login down for every team at once.

Session state lives in Redis with a short TTL, and every authentication event is written to an append-only audit log in PostgreSQL, so security teams can reconstruct exactly who signed in to what, and when, without touching the directory server itself.

The whole stack is built to be boring on purpose: a handful of small services, a managed cache, a managed database, and no long-lived state beyond a session token. Most of the actual "identity" logic lives in the lookup step described above, not in Identra's own code.

Why we kept the integration this small

Teams evaluating Identra often expect a bigger system — a dedicated user store, a sync job, a reconciliation process. We deliberately left all of that out. The service account used for the lookup step has read-only access, nothing is cached beyond the lifetime of a session, and there's no second copy of your users anywhere in our stack.

That smaller footprint is also why the deployment is just a couple of containers and a config file — most teams finish rollout in an afternoon, including testing against a staging environment.
